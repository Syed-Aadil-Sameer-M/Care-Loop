PHASE 01 Foundation — Scaffold, NLP, DB, State Machine Days 1–2 Everything talking to everything before Day 3
DAY 1 — Monday
Project scaffold + NLP live
Project scaffoldINFRA
Init all three repos. Get them talking before writing any feature code.
How: npx create-react-app careloop-ui, npm init + express for Node backend, fastapi + uvicorn for Python NLP. Connect via .env. Push to GitHub immediately.
Supabase + PostgreSQL liveINFRA
Create 4 tables: patients, care_journeys, care_actions, audit_log. Get connection string in .env.
Tables: care_actions needs columns — id, journey_id, type, status, confidence, owner, deadline, depends_on[], created_at. audit_log needs — action_id, from_state, to_state, actor, timestamp, note.
NLP extraction endpointAI · WOW
POST /extract takes raw doctor note. Returns JSON array of care actions. This is the backbone of everything.
How: Call Claude API with a system prompt that says "Extract all medical orders from this note. Return JSON array: [{action, type, confidence, dependencies}]. type is one of: test | referral | medication | followup. confidence is 0–1." Parse and store.
Confidence classificationAI · WOW
Tag each action: Explicit (>0.85 → execute), Conditional (0.5–0.85 → flag), Ambiguous (<0.5 → hold for human).
How: Add classification logic in Python after API response. Include phrasing signals in prompt — "order ECG" = Explicit, "consider cardiology" = Conditional.
⚡ Day 1 advice Don't build UI today. Just get the NLP call returning data in your terminal. If /extract returns a clean JSON array by end of Day 1, you're on track. Everything else is downstream of this call.
DAY 2 — Tuesday
State machine + dependency graph + mock APIs
Care action state machineCORE
Every action lives in one of 10 states. Transitions are the only way to move between them.
States: CREATED → VALIDATED → ASSIGNED → SCHEDULED → IN_PROGRESS → COMPLETED → VERIFIED | exceptions: BLOCKED, OVERDUE, ESCALATED. Build a transitionState(actionId, newState, actor) function. Every call writes to audit_log.
Dependency graph builderAI · WOW
After extraction, link actions in clinical order. Doctor review can't start until ECG + blood test are VERIFIED.
How: In Claude prompt add "also return depends_on: [] listing action types that must complete first." Store as a depends_on array in DB. Build a isUnblocked(actionId) check that queries all dependencies.
Mock APIs — lab, referral, pharmacyBACKEND
Three fake endpoints that simulate external hospital systems. The agent calls these to "execute" orders.
How: Build inside the Node backend: POST /mock/lab/book → returns {slotId, datetime, status:"booked"}, POST /mock/referral/send → returns {refId, dept, status:"sent"}, POST /mock/pharmacy/notify → returns {rxId, status:"logged"}. Add random 10% failure rate to test self-healing.
Auth — Firebase / JWTINFRA
Three roles: doctor, coordinator, patient. Don't over-engineer. Simple JWT middleware is fine.
How: Firebase Auth is fastest — 30 mins to set up. Add role claim to Firebase user. Middleware checks role on every protected route. Hardcode 3 demo accounts: doctor@careloop.dev, coord@careloop.dev, patient@careloop.dev.
⚠ Critical checkpoint By end of Day 2: paste a doctor's note → get actions in DB → state machine can transition them → mock APIs respond. If any of these don't work, fix before Day 3. Don't build on a broken foundation.
PHASE 02 Agent Core — Executor, Self-Healing, WhatsApp, Dashboard Days 3–4 The "wow" moment — paste note, watch system execute
DAY 3 — Wednesday
Autonomous executor + LLM function calling
LLM function calling agentAI · WOW
The centrepiece. LLM decides which mock API to call, calls it, handles the response — all autonomously. This is what separates CareLoop from a tracker.
How: Use Claude API with tool_use. Define tools: book_lab_test(patient_id, test_type), send_referral(patient_id, dept), notify_pharmacy(patient_id, medication), schedule_followup(patient_id, days). Pass extracted actions to Claude as user message: "Execute these care actions using the available tools." Let Claude call them in dependency order. Poll tool_use blocks from response.
Execution orchestratorCORE
Node.js service that: checks dependency graph, calls agent for unblocked actions, updates state machine on result.
How: async function executeJourney(journeyId) — fetch all actions, filter to unblocked + VALIDATED, call LLM agent, for each tool_use result call transitionState() to SCHEDULED or ASSIGNED. Run this after every extraction.
Self-healing retry engineCORE · WOW
When a mock API returns failure: retry with alternate slot → alternate department → then and only then escalate to coordinator.
How: Wrap every mock API call in try-catch. On failure: increment retry_count in DB. retry_count 1 → call same API with different slot param. retry_count 2 → call API with alt_dept param. retry_count 3 → transitionState(ESCALATED) and push to exception queue. Log all retries to audit_log.
E2E test run #1QA
Paste Ramesh's exact note. Verify: 4 actions extracted, dependency graph correct, all 4 execute via agent, states update, audit log has entries.
Check: ECG and blood test should execute immediately. Doctor review should remain BLOCKED. Cardiology referral should execute. If self-healing is wired, kill one mock API and verify retry fires.
🏆 Day 3 is your biggest day If LLM function calling works by end of Day 3, you have the core wow feature. Everything from Day 4 onward is making it presentable. If it's struggling, fall back to hardcoded executor logic — the agent narrative still holds, you just don't call it function calling.
DAY 4 — Thursday
WhatsApp + gap detector + coordinator dashboard
WhatsApp patient notificationCOMMS · WOW
After execution, patient receives a WhatsApp message with their bookings and a one-tap confirm link. This is the demo's most visceral moment — judges see a real phone buzz.
How: Twilio WhatsApp Sandbox (free). Pre-approve your demo phone on Day 1 at twilio.com/console. After agent executes: client.messages.create({from:'whatsapp:+14155238886', to:'whatsapp:+91XXXXXXXXXX', body:'Done ✅ — ECG booked tomorrow 9am. Cardiology referral sent. Reply YES to confirm.'}). On YES reply webhook → transition action to CONFIRMED.
Care gap detectorCORE · WOW
Cron job that runs every 5 minutes. Checks all active journeys for 5 broken transition types.
5 gap types to detect: 1) action in CREATED state >1hr with no VALIDATED transition, 2) action SCHEDULED but no IN_PROGRESS after deadline, 3) action COMPLETED but no doctor review triggered within 2hrs, 4) action OVERDUE — deadline < now and not VERIFIED, 5) dependency completed but blocked action not unblocked. On detection → transition to OVERDUE or ESCALATED + push to exception queue.
Coordinator exception dashboardUI
Coordinators see ONLY what the agent couldn't resolve. Not all patients. Not all tasks. Just the exceptions. This is the counterintuitive wow — a mostly empty dashboard means the system is working.
Build: React page. Fetch all actions with status IN [ESCALATED, OVERDUE]. Show: patient name, action type, failure point, how many retries failed, time overdue. One button: "Resolve manually" → calls resolve endpoint → logs coordinator action → removes from list. Empty state message: "No exceptions — agent handled everything."
Doctor note input + action viewUI
Doctor's screen: textarea for note, submit button, extracted actions appear in real time with confidence badges.
Build: On submit → POST /extract → stream actions to screen one by one with a 300ms stagger animation. Show each action: name, type badge, confidence %, status chip. This is the live demo's opening moment — make it visually satisfying.
⚡ Day 4 advice Approve your Twilio WhatsApp sandbox number today. It takes 30 mins and you need it live before the demo. Send yourself a test message now, not on Day 7.
PHASE 03 Demo Scenario + UI Polish + Deploy Days 5–6 Judges see it work. On a live URL. Without bugs.
DAY 5 — Friday
Ramesh demo scenario + audit trail + patient view
Ramesh demo scenario — seeded dataDEMO · CRITICAL
Pre-seed the DB with Ramesh's patient profile. When you paste his doctor's note on stage, the system already knows who he is and the journey runs instantly.
Seed script: Insert Ramesh Kumar, 62M, phone +91XXXXXXXXXX. Pre-register this number in Twilio sandbox. Demo flow: paste note → 4 actions extracted (show stagger animation) → agent executes (show API calls in log) → WhatsApp sent (show on phone) → actions in SCHEDULED state → journey timeline shows green ticks. Practice this exact sequence until it takes 90 seconds.
Live agent execution logDEMO · WOW
A real-time panel that shows the agent's decisions as they happen. Judges watch: "calling lab API… booked slot 09:00… sending referral to cardiology… done." This is cinema.
How: Server-sent events (SSE) or WebSocket from Node backend. Every time the agent calls a tool or transitions a state, emit an event. Frontend shows a scrolling log panel with timestamp, action, and result. Use a monospace font. Green for success, amber for retry, red for escalation.
Full audit trail UIFEATURE
Replayable timeline of every state change. Demonstrates accountability — every autonomous decision is logged.
Build: React timeline component. Fetch audit_log for a journey. Show each entry: icon (agent/human/system), timestamp, "ECG → SCHEDULED by agent", "retry #1 — alternate slot booked". Judges love this — it shows you thought about production, not just the happy path.
Doctor closure notificationFEATURE
When all actions in a journey reach VERIFIED — automatically notify the doctor. The loop is closed.
How: After every transitionState(VERIFIED) call, check if all sibling actions are VERIFIED. If yes → send email/in-app notification to doctor: "Ramesh Kumar's care journey is complete. All 4 actions verified." Update journey status to CLOSED in DB.
⚡ Day 5 advice Run the full demo scenario 5 times today. Time it. It should take 90 seconds max. If it takes 3 minutes, something is wrong — find the bottleneck and fix it. The live execution log is optional if time is tight — but it makes the demo 10× more impressive.
DAY 6 — Saturday
UI polish + deploy + buffer
UI consistency sweepDESIGN
One pass through every screen. Fix spacing, font sizes, color inconsistencies. It doesn't need to be beautiful — it needs to look intentional.
Checklist: Consistent padding (16px or 24px, pick one). Same font size for all labels. Status badges same style everywhere. Loading states on every async action. Empty states have copy (not blank screens). Buttons have hover states. Forms have validation feedback.
Patient journey timeline viewUI
A visual view of Ramesh's care journey — each step with status icons. This is what you show when you say "the patient can see exactly what was promised."
Build: Vertical timeline. Each action: icon (test/referral/pill/calendar), name, status chip (Done ✅ / Pending ⏳ / Gap ❌), date. Show dependency lines between connected steps. Mobile-friendly — show this on your phone during demo.
Deploy — Vercel + RailwayINFRA · CRITICAL
Frontend on Vercel. Node backend + FastAPI on Railway. Both must be live before Day 7. Never present from localhost.
How: Vercel: connect GitHub repo, set REACT_APP_API_URL env. Railway: deploy Node and Python services separately, set all env vars (Supabase URL, Claude API key, Twilio creds). Test every endpoint from the live Vercel URL. Note: Railway free tier sleeps after 30min inactivity — ping services or upgrade $5/mo for demo weekend.
Buffer — fix anything brokenQA
Half of Day 6 is reserved for fixing things that broke in Days 1–5. Do not fill this time with new features.
Priority order for fixes: 1) Demo scenario must run cleanly, 2) WhatsApp must send on live URL, 3) coordinator dashboard must load, 4) audit trail must show entries. Everything else is cosmetic.
⚠ Deploy warning Cold starts on Railway free tier can take 15–30 seconds. During the demo this looks like your app is broken. Upgrade to the $5 plan OR set up an UptimeRobot ping every 5 minutes to keep services warm. Do this on Day 6, not Day 8 morning.
PHASE 04 Pitch + Rehearse + Win Days 7–8 Judges remember you when results are announced
DAY 7 — Sunday
Pitch deck + demo script + rehearsal ×3
Pitch deck — 7 slides maxPITCH
Do not spend more than 2 hours on this. Slides are supporting material — the live demo is the pitch.
Slide order: 1) Ramesh's story (the problem, one slide, one paragraph, no bullets), 2) The gap in one sentence, 3) "CareLoop doesn't remind — it executes" (full slide, nothing else), 4) Live demo (this is where you switch to the app), 5) How it works (dependency graph + confidence scoring), 6) Tech stack (one slide, humble, confident), 7) Impact + "What if every mid-tier hospital had this?"
Demo script — written and timedPITCH
Write the exact words you'll say during the live demo. 90 seconds. Every second planned.
Script: "Ramesh Kumar, 62, chest pain. Doctor writes this note." [paste note] "Watch what happens." [pause — actions appear] "Four care actions extracted, in under 2 seconds." [pause] "The agent is now executing them." [log panel scrolls] "ECG booked. Lab notified. Referral sent. And —" [phone buzzes] "Ramesh just got a WhatsApp." [show phone] "He hasn't been waiting. He hasn't been chasing. He just got told it's done." [pause] "No human pressed a button."
Rehearse ×3 — full run with timerPITCH
Every team member does the full pitch + demo at least once. The person demoing must be able to do it in the dark.
Rules for rehearsal: Use the live URL, not localhost. Have a phone with Twilio pre-approved. Time every run. Cut anything that makes it go over 4 minutes total. If the live demo takes >90 seconds, find the bottleneck. Practice the Q&A: "Why not just use an EHR?" / "How do you handle wrong extractions?" / "What's the business model?"
Record fallback videoSAFETY
Record the perfect demo run as a video. If WiFi fails, play the video. No exceptions to this rule.
How: Use OBS or QuickTime. Record your screen + the phone WhatsApp moment. Edit to exactly 90 seconds. Export as MP4, bring on USB stick AND uploaded to Google Drive. Practice saying "Let me also show you on video" smoothly — it should not sound like a failure.
🏆 The winning mindset for Day 7 After 3 rehearsals, stop. You know the demo. Overshooting rehearsal makes you robotic. Get 8 hours of sleep. Tomorrow's energy matters more than tonight's practice.

Risk register — read this on Day 1, not Day 7
Risk Level What it looks like Exactly what to do
LLM function calling doesn't work cleanly High Agent calls wrong tool or returns errors on stage Fallback: Hardcode the executor — if action.type==='test' call bookLab(), etc. The demo still shows autonomous execution. The "LLM decides" story becomes "rules-based agent" — still impressive, still different from a tracker.
Claude API is slow (>5s) High Demo stalls on stage — awkward silence, judges lose interest Cache the Ramesh response. First time you run the extraction, store the result in DB. On demo, check cache first — if exists, return immediately. Add a "using cached response" label. Judges don't care. Speed does.
Twilio WhatsApp sandbox limit Medium Message doesn't arrive live on stage Approve your demo phone on Day 1. Test it 10 times before Day 8. If it fails on stage, have a screenshot of the WhatsApp on your phone from the last test run. Show the screenshot. Say "here's what Ramesh receives."

WiFi fails on stage Medium Live demo dead Record the full demo video on Day 7. Bring it on USB + Google Drive. Practice saying "I'll show you the live URL after — let me play the recording first." Smooth delivery kills the awkwardness.
Scope creep — building too much High Core features half-working by Day 6 Rule: If a feature is not in this roadmap, it does not get built. After Day 5, no new features. Only fixing and polishing. A clean demo of 10 features beats a broken demo of 15.
Team member didn't finish their part Low Key feature missing before demo Assign owners now. Each phase has a lead. If someone falls behind by Day 4 — redistribute, don't wait. Drop the lowest-priority feature and make sure the demo scenario works end-to-end.
Win conditions — three things that guarantee the result

Demo that lands

  • Open with Ramesh's story — not a slide, not features
  • Paste the note live. Watch the system go.
  • Show the WhatsApp arrive on a real phone
  • Flip to coordinator dashboard — it's empty
  • Say "No human pressed a button." Then stop.
  • Fallback video ready if WiFi dies
  • Total demo time: 90 seconds. Not one second more.

Tech judges respect

  • LLM function calling — the modern agentic AI pattern
  • Dependency graph — real system design thinking
  • Confidence-gated autonomy — nuance, not binary
  • Self-healing retries — production-aware
  • SSE real-time log — shows you understand async
  • Deployed live URL — not localhost
  • Clean GitHub README — one-line setup

Pitch that sticks

  • One sentence: "CareLoop doesn't remind — it executes"
  • India mid-market angle — specific, not generic
  • The 40% stat — ordered tests never completed
  • Three-tier intervention (agent → coordinator → doctor)
  • Every team member answers: "what did you build?"
  • Q&A prep: EHR question, accuracy question, scale question
  • End with the one-liner. Every. Single. Time.
